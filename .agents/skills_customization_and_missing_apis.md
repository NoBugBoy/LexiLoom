> **编制说明**：本文档针对「本地代码仓库 + LexiLoom 知识库多路混合检索」功能，梳理采用 **Agent Skills 机制** 落地时，后端系统需要做的
> **定制改造点**、 **架构调整**以及 **当前系统所缺失的核心 API**。

---

## 一、架构设计理念：为什么选择 Skill + 本地绑定模型？

在结合「本地工程代码」与「远程知识库」时，若完全依赖后端克隆 Git 仓库，会面临私有仓库认证复杂、大仓库克隆耗时大、分支代码实时性差、云端重复向量化浪费算力等一系列问题。

而通过 **Skill（Agent 技能包）** 的方式：

1. **天然持有本地代码上下文**：CLI / IDE 插件运行在当前工作区，通过本地 `ripgrep` 实现 0 云算力、0 延迟、100% 实时的精准代码检索；
2. **免安装与团队共享**：Skill 直接位于工程目录 `.agents/skills/lexiloom-hybrid-search/`，纳入 Git 版本控制后，团队所有成员
   `git pull` 即可立即可用；
3. **一次绑定，无感使用**：通过 `.lexiloom/config.json` 将本地项目与云端工作空间绑定，后续提问无需每次手动选择空间或输入复杂参数。

## 三、针对 Skills 做出的定制与架构演进

### 1. 数据库层面改造 (Database Schema)

#### ① 后台管理员 API Key 实体表 (`ll_admin_api_key`)【已落地】

为了支持 CLI/Agent 的无状态长效认证，系统按 **管理员全局唯一**模型（基于 `ll_admin` 后台用户体系）设计并落地了 API Key 实体：

* **单一原则**：每个管理员全局仅维护一个 API Key，避免空间繁杂配置；
* **永不过期**：作为等同于永久 Token 的管理员接入凭证，自动继承管理员角色（`ADMIN`/`SUPER_ADMIN` 等）；
* **支持轮转与即时失效**：支持重新生成（轮转），旧 Key 立即失效并自动从 Redis 缓存中清除；
* **自愈建表**：纳入 `DatabaseSchemaInitializer` 自动完成表结构与唯一索引巡检。

```sql
CREATE TABLE IF NOT EXISTS ll_admin_api_key
(
    id             BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    admin_id       BIGINT       NOT NULL, -- 关联管理员 ID (全局唯一)
    api_key        VARCHAR(128) NOT NULL, -- 密钥明文串 (lx_live_xxx, 全局唯一)
    name           VARCHAR(128),          -- 备注名称 (如 Default CLI Key)
    last_used_time TIMESTAMP,             -- 最近一次成功鉴权调用时间
    create_time    TIMESTAMP    NOT NULL,
    update_time    TIMESTAMP    NOT NULL,
    create_by      BIGINT,
    update_by      BIGINT,
    del_flag       BIGINT DEFAULT 0       -- 逻辑删除标识
);

CREATE UNIQUE INDEX IF NOT EXISTS idx_admin_api_key_aid ON ll_admin_api_key (admin_id, del_flag);
CREATE UNIQUE INDEX IF NOT EXISTS idx_admin_api_key_key ON ll_admin_api_key (api_key, del_flag);
```

#### ② 观测主表 (`ll_ai_rag_trace`) 补充调用源【已落地】

在 [`ll_ai_rag_trace`](file:///Users/yujian/Downloads/trade/src/main/resources/schema_rag_trace.sql#L7) 表及实体中追加字段：

### 2. 安全过滤链改造 (Spring Security)【已落地】

`AuthenticationFilter` 已完成双轨鉴权升级：

* **双通道支持**：同时支持 `Authorization: Bearer <key>` 与 `X-API-Key: <key>` 请求头；
* **分流鉴权**：
    1. 若 Token 以 `lx_` 开头或通过 `X-API-Key` 传入，走 `UserApiKeyAuthApi` 验证；
    2. 优先命中 Redis 高速无过期缓存 (`user:apikey:{key}` -> `userId`)，若未命中则查库并回写缓存；
    3. 异步通过虚拟线程 (`Thread.ofVirtual()`) 更新 `last_used_time`，并配置 1 分钟防刷写降噪；
    4. 校验通过后自动注入 `LoginUserAuthentication(userId)` 到 `SecurityHolder`；
    5. 兼容普通 Web 登录用户的 `RedisTokenManager` 流程。

---

### 3. 服务层下沉解耦：拆分“纯切片检索”与“LLM问答”

* **现状问题**：现有的 [
  `DefaultRagChatService`](file:///Users/yujian/Downloads/trade/src/main/java/io/lexiloom/application/ai/rag/DefaultRagChatService.java)
  内部，检索召回、重排序和 LLM 大模型生成是紧密耦合在一个方法中的。
* **改造动作**：
    - 将其中的检索管线抽离为独立的查询接口：
      ```java
      public interface KnowledgeRetrievalQueryService {
        /**
         * 纯语义检索与重排，不调用大模型生成答案
         */
        List<DocChunkDocument> retrieveChunks(Long workspaceId, String query, int topK, Double minScore);
      }
      ```
    - `DefaultRagChatService` 仅需调用该服务获取切片，再拼接 Prompt 交给大模型；
    - 新增的 Skill 专用 Controller 也复用该接口，直接返回切片 DTO，实现 **毫秒级无头检索**。

## 四、当前系统核心 API 契约与待补充接口

### 1. 全局用户 API Key 管理接口【已落地】

* **端点**：
    - `GET /user/api-key`：获取当前登录用户的 API Key 信息（包含 `hasApiKey`, `apiKey`, `lastUsedTime` 等）
    - `POST /user/api-key?name=xxx`：为当前登录用户生成或重新生成（轮转）API Key
    - `DELETE /user/api-key`：吊销删除当前登录用户的 API Key (返回 204)

---

### 2. 工作空间轻量列表发现接口【已落地】

* **端点**：`GET /api/ai/mcp/workspaces`
* **鉴权方式**：`Authorization: Bearer lx_...` 或 `X-API-Key: lx_...`
* **职责**：`setup.sh` 初始化脚本调用，列出当前登录用户具备访问权限的工作空间。
* **响应示例**：
  ```json
  [
    {
      "id": 1,
      "name": "LexiLoom 核心研发空间",
      "description": "后端架构设计与领域模型规范",
      "totalDocuments": 42,
      "totalChunks": 1560
    }
  ]
  ```

---

### 3. 知识库切片轻量纯检索接口 (核心)【已落地】

* **端点**：`GET /api/ai/mcp/search` 与 `POST /api/ai/mcp/search`
* **鉴权方式**：`Authorization: Bearer lx_...` 或 `X-API-Key: lx_...`
* **Query 参数**：
    - `q`（必填）：检索自然语言 Query
    - `workspaceId`（可选）：指定空间（默认使用绑定的空间）
    - `topK`（可选，默认 5）：召回上限
    - `minScore`（可选，默认 0.5）：相似度截断阈值
* **响应示例**：
  ```json
  {
    "query": "Token 统计计算规则",
    "workspaceId": 1,
    "totalMatches": 8,
    "results": [
      {
        "chunkId": "chunk_0192a8e1",
        "documentId": 88,
        "documentTitle": "RAG 链路观测与成本治理方案",
        "categoryName": "技术规范",
        "content": "统计指标必须覆盖全周期总计、各模型独立占比以及连续 7 天按日零填充折线图序列...",
        "score": 0.935,
        "chunkIndex": 2,
        "pageNumber": 1,
        "deepDocCoordinates": "[{\"x\":100,\"y\":200,\"w\":400,\"h\":150}]"
      }
    ]
  }
  ```

---

### 4. 单文档完整正文/大纲提取接口【已落地】

* **端点**：`GET /api/ai/mcp/documents/{id}`
* **鉴权方式**：`Authorization: Bearer lx_...` 或 `X-API-Key: lx_...`
* **职责**：当 Agent 发现某一文档与代码差异巨大、需要通读整篇长文时，获取未切分的 Markdown 正文。
* **响应示例**：
  ```json
  {

    "title": "RAG 链路观测与成本治理方案",
    "workspaceId": 1,
    "categoryName": "技术规范",
    "status": "APPROVED",
    "content": "# RAG 链路观测与成本治理方案\n\n## 1. 背景...",
    "updateTime": "2026-10-21 15:30:00"
  }
  ```
